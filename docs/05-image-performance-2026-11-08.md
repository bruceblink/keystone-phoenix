# 镜像大小与性能测量

日期：2026-11-08。范围：本机 Linux AMD64 生产 release 镜像。没有推送镜像或创建发布标签。

## 术语与范围

| 指标 | 本报告中的含义 |
| --- | --- |
| 镜像大小 | 分别记录 `docker images`、Engine API 的 `Size` 和本地压缩归档；各值的口径不同 |
| CPU 使用率 | 容器 CPU 时间除以墙钟时间；`100%` 表示一个逻辑 CPU |
| 内存工作集 | 容器 cgroup 内存减去 `inactive_file`，是活动内存的近似值 |
| 请求延迟 | 客户端建立 TCP 连接、获取完整响应的耗时；列出 p50、p95 和 p99 |
| 服务器端渲染（Server-Side Rendering / SSR） | 应用返回登录页 HTML，不包含浏览器资源加载和长连接 |

`MB` 为 1,000,000 字节，`MiB` 为 1,048,576 字节。应用和 PostgreSQL 容器分别采样，不把数据库内存计入应用内存。开发服务器未用于本次测量。

## 镜像与构建

测量时 Git 基线为 `cc4ced0`。镜像还包含当时工作区内尚未提交的认证、用户范围和页面改动，因此不能把性能结果归因于该提交的原始源码。输入包括 `Dockerfile`、`.dockerignore`、`mix.exs`、`mix.lock`，以及 `config/`、`lib/`、`priv/`、`rel/` 下的文件。

构建使用 `elixir:1.20.5-otp-29` 和 `debian:trixie-slim`。本机首次构建使用 `debian:bookworm-slim`，release 启动时因缺少 `GLIBC_2.38` 失败。构建阶段实际为 Debian 13，改用 Debian 13 运行阶段后，迁移和启动成功。

网络下载 Hex 包超时后，测试使用本机已有的 Hex 包缓存。临时构建文件相对仓库 Dockerfile 仅增加构建阶段缓存输入；生产依赖版本和最终运行阶段没有因此改变。真实构建仍使用 `mix.lock`。构建阶段未使用缓存时的完整构建耗时未取得。

本次测量的镜像为 `keystone-phoenix:local-metrics-20261108`：

| 口径 | 实际结果 |
| --- | ---: |
| Docker CLI `docker images` | 238 MB |
| Docker Engine image inspect `Size` | 61,829,451 字节，约 58.97 MiB |
| `docker save` 后以 `gzip -1` 压缩的归档 | 61,350,385 字节，约 58.51 MiB |
| 镜像 ID | `sha256:48c390659064f876e5acc948f104cb0f40cdc33b892d738f709f647222371ead` |

Docker Engine 使用 containerd image store，CLI 和 Engine API 的大小口径不同。压缩归档不是镜像仓库实际网络传输量。

随后将运行阶段 Debian 软件包源改为清华大学开源软件镜像站，并构建、迁移和启动另一镜像 `keystone-phoenix:local-metrics-cn-20261108`。它的 Docker CLI 大小为 238 MB，Engine `Size` 为 61,829,512 字节，压缩归档为 61,351,892 字节，镜像 ID 为 `sha256:9fecf14b4c881b2328155348b6e92635d9ae7faf189c5b14c725cdc1cfd69cf3`。该镜像的首页和数据库就绪检查均返回 `200`，但下文性能数据来自切换软件包源之前的镜像，不声称测过新镜像的性能。

后一个镜像的输入包括 113 个文件，指纹为 `9edeaad4dee26bc8e2807e28e59ccc07dd3ccec20832c3b21bb57c4e8bed414d`。计算方法：递归读取上述目录中的文件，将相对路径统一为 `/`，对 `相对路径=文件 SHA256` 按 Ordinal 顺序排序，以 LF 连接且末尾不加换行，再计算 UTF-8 字节的 SHA256。

同机两次构建中，Debian 软件包索引下载从官方源约 198 秒降为清华源约 2 秒。两次存在缓存和网络状态差异，这不是稳定速度承诺。镜像站的安全更新可能有同步延迟；软件包仍通过 Debian 软件源签名校验。

后续将 Docker Hub 基础镜像地址切换为 DaoCloud 镜像地址，将 Hex 源切换为 UPYUN 提供的非官方镜像。2026-11-08 核验的 Elixir 和 Debian 镜像摘要与本次测试使用的官方镜像摘要一致；本机下载的 `phoenix_live_view-1.2.13` 包与 UPYUN 镜像内容的 SHA-256 一致。镜像内容可能存在同步延迟；构建回退命令见 [`04-deployment-runbook.md`](04-deployment-runbook.md)。

最终使用仓库 Dockerfile 的国内地址完成构建，没有注入本机 Hex 包缓存。9 项空库迁移成功，首页和数据库就绪检查均返回 `200`。该镜像 `keystone-phoenix:domestic-mirrors-20261108` 的 Docker CLI 大小为 238 MB，Engine `Size` 为 61,830,163 字节，压缩归档为 61,353,673 字节，镜像 ID 为 `sha256:66c59d446575acad31e52bf8177990d5c626136afbd332a8861eac4195327fea`。本次没有对最终镜像重新执行性能负载；下文数据仍对应先前的测量镜像。

## 测试环境与方法

| 项目 | 配置 |
| --- | --- |
| 主机 | AMD Ryzen 9 5900X，12 核、24 逻辑 CPU；物理内存 51,481,890,816 字节 |
| WSL | Ubuntu 24.04.4，WSL 2；内核 `6.6.114.1-microsoft-standard-WSL2` |
| Docker | Engine `29.1.3`；可用内存 25,167,966,208 字节 |
| 应用容器 | 限制 2 个 CPU、512 MiB；只监听本机 `127.0.0.1:4401` |
| 数据库容器 | `postgres:18`，实际 PostgreSQL `18.6`；没有设置容器 CPU 和内存上限 |
| 数据隔离 | 独立 bridge 网络和空数据库；执行 9 项镜像内迁移，不导入开发账号 |

测试先预热 5 秒，空闲 10 秒，再分别对 `GET /` 和 `GET /health/ready` 各执行一次 30 秒测试。每项使用 8 个闭环线程；两项之间间隔 5 秒，结束后空闲 10 秒。采样计划约 90 秒，低于五分钟。每次请求新建连接，客户端与应用共享同一 WSL 主机。

`/health/ready` 每次访问 PostgreSQL 执行 `SELECT 1`。采样器分别读取两个容器的 Docker Engine 数据；CPU 平均值按采样间隔加权。两次负载各有 14 个有效样本；阶段切换期间的样本不计入统计。两个采样器的错误数均为 0。

## 请求结果

| 接口 | 请求数 | 错误数 | 吞吐 | p50 | p95 | p99 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `GET /` | 64,955 | 0 | 2,164.82 次/秒 | 3.57 ms | 5.49 ms | 6.52 ms |
| `GET /health/ready` | 65,095 | 0 | 2,169.54 次/秒 | 3.56 ms | 5.39 ms | 6.44 ms |

两项正式负载的响应均为 HTTP `200`。预热请求不计入表内请求数。吞吐受到同机客户端、调度和网络开销影响，不是最大容量。

## CPU 与内存

| 阶段 | 应用 CPU 平均/采样峰值 | 应用工作集平均/采样峰值 | PostgreSQL CPU 平均/采样峰值 | PostgreSQL 工作集平均/采样峰值 |
| --- | ---: | ---: | ---: | ---: |
| 预热后空闲 | 0.37% / 0.46% | 162.21 / 162.42 MiB | 2.06% / 2.11% | 55.69 / 55.95 MiB |
| 首页 SSR 负载 | 157.90% / 159.36% | 163.62 / 165.39 MiB | 2.32% / 4.73% | 56.10 / 56.29 MiB |
| 数据库就绪负载 | 167.82% / 169.30% | 163.56 / 163.82 MiB | 30.00% / 31.07% | 56.74 / 57.54 MiB |
| 负载后空闲 | 0.32% / 0.51% | 163.21 / 163.30 MiB | 2.40% / 2.91% | 57.23 / 57.55 MiB |

这是采样期间的峰值，不保证捕获所有瞬时峰值。应用容器在首页负载期间的 cgroup 内存平均值为 163.76 MiB，观测峰值为 165.53 MiB；就绪检查负载期间分别为 163.70 MiB 和 163.96 MiB。两个容器在测试结束时均未发生内存不足终止，重启次数均为 0。

## 限制与清理

本次没有测量已登录 LiveView、业务写入、密码哈希、文件上传下载、大数据量、多节点、长期负载或公网延迟，不能用来给出生产容量承诺。短时测试也不能替代独立压力测试或发布验收。

两个测试使用的临时应用容器、空数据库容器和专用网络已清理。原有持久 PostgreSQL、Redis 和浏览器验收数据库保留。镜像与原始采样文件保留在本机；采样文件位于本任务的 `keystone-metrics/` 证据目录。
