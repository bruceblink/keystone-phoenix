# Keystone Phoenix 开发计划

## 目标

将 Keystone 的本地账号、组织权限、系统管理、监控、定时任务和管理前端迁移到 Elixir、Phoenix、Ecto、PostgreSQL 和 LiveView。第一阶段以功能完整、可部署和可持续迭代为验收标准；`bruceblink/keystone-frontend` 只作为接口参考，不要求视觉或实现方式 1:1 复刻。第二阶段把实现重构为更符合 Elixir/OTP 的形式，并降低运行和部署成本。

项目现在只需要 PostgreSQL。认证会话保存于 `auth_sessions` 表；验证码、字典缓存和配置缓存使用应用进程内 ETS。ETS 只保存可以重建的短期数据，PostgreSQL 是业务数据和认证状态的唯一持久化来源。

## 阶段状态

### 第一阶段：功能重写

第一阶段的主要功能已经完成：

1. 健康检查、PostgreSQL 迁移和种子数据。
2. 字典类型/数据、系统配置、用户、部门、岗位、角色、菜单、角色授权和公告 CRUD。
3. RSA 登录密码解密、RS256 access/refresh token、单账号登录、刷新轮换、强制下线和密码变更撤销会话。
4. 登录日志、操作日志、敏感参数脱敏、头像上传和资源访问。
5. 定时任务定义、调用目标白名单、Cron 调度、执行日志、超时和取消。
6. LiveView 登录、组织权限、账号资料、系统设置、字典、公告、日志、任务和监控页面。
7. HTTP API 与 LiveView 集成测试、PostgreSQL 数据测试、GitHub Actions 测试和 release 镜像构建。

### 第二阶段：去 Redis 和 Elixir 化重构

基础设施简化切片已完成，后续按下面的顺序继续优化：

1. **认证会话迁移**：已新增 `auth_sessions` 表，用事务和 PostgreSQL advisory lock 保证单账号会话；登录、刷新、强制登录、退出、禁用用户和管理员强制下线均已接入。
2. **临时数据迁移**：已用应用拥有的 ETS 表保存验证码和可重建缓存，加入过期时间、定期清理和缓存统计。
3. **依赖与部署清理**：已移除 Redix、Redis 配置、Redis Compose 服务、Redis CI 服务和 Redis readiness 检查；保留 `/monitor/cacheInfo` 路径，返回 ETS 缓存统计以兼容现有前端。
4. **数据访问优化**：已消除在线用户、部门树和菜单树的主要 N+1/O(n²) 查询路径；继续优化角色授权和日志列表。
5. **认证并发测试**：已覆盖会话创建、重复登录、强制登录、撤销和过期查询；下一步增加并发刷新和多实例验证。
6. **运行时观测**：已用 ETS 统计替代外部缓存服务指标；下一步补充 Telemetry 请求耗时、任务执行和数据库连接池指标。

### Java 兼容补齐状态

代码审查后已按缺口顺序完成通用文件、Excel、字典缓存、角色权限与数据范围、ETS 限流/防重复提交、组织树一致性、前端实际调用的路由别名和过期会话清理。监控 CPU 已改为 OTP 周期快照，在线用户查询增加分页边界。当前 `main` 是可用版本基线；详细矩阵见 [`02-java-parity.md`](02-java-parity.md)。

## 后续开发顺序

1. 统一领域层的参数解析、分页、过滤和 JSON 映射，减少重复样板。
2. 将 `LoginLive` 的认证状态、dashboard 初始状态和登出状态抽到独立状态模块，继续保持每个源文件不超过 600 行。
3. 重构定时任务调度器，优化任务定义缓存、触发计算和日志写入。
4. 增加 Telemetry 请求耗时、任务执行和数据库连接池指标。
5. 按实际部署需求补充 MySQL ETL、浏览器测试和备份恢复工具。

## 每个切片的验收条件

- 数据库迁移只追加，不修改已经共享的迁移；迁移可在空库和现有开发库执行。
- 未登录请求返回现有 `40101` 响应；管理员接口对普通用户返回 `40301`。
- 会话写入、刷新、撤销和强制下线在事务边界内完成，过期会话不能恢复为有效状态。
- ETS 只保存可丢失数据；应用重启后验证码和缓存可以重新生成，业务数据和会话不丢失。
- 密码、令牌、验证码和上传路径不出现在响应、日志或普通缓存中。
- 每个新增行为有针对真实实现的单元测试或数据库测试，并运行格式、严格编译、源文件行数、默认测试和集成测试。
- 每个源代码文件不超过 600 行；领域功能完成后先形成独立提交，再开始下一个切片。
- LiveView 改动验证页面渲染、事件处理和失效会话行为；有可用浏览器窗口时补充真实窗口联调。

## 本地验证命令

```bash
docker compose up -d postgres
mix setup
mix format --check-formatted
mix check.source_lines
mix test
mix test --include integration
mix precommit
```

生产 release 需要 `DATABASE_URL`、`SECRET_KEY_BASE`、`JWT_PRIVATE_KEY` 和 `PHX_HOST`。ETS 属于当前 BEAM 节点；如果未来需要跨节点共享临时数据，应先评估 PostgreSQL 表或其他共享存储，而不是把 ETS 当作分布式缓存。

## 回滚边界

每个功能切片使用独立提交。Redis 移除属于一次完整迁移：先部署会话表和 ETS 实现，再删除 Redix 与 Redis 配置。切换后旧 Redis 会话不会迁移，首次部署会要求用户重新登录；数据库迁移和应用代码必须一起发布。出现问题时回滚应用版本，并保留新增会话表，避免破坏已有 PostgreSQL 数据。
