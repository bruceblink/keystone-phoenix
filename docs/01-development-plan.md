# Keystone Phoenix 开发计划

更新日期：2026-11-07。代码基线：`main` 的 `455cf82`。审查依据和问题编号见 [`03-code-review.md`](03-code-review.md)。

## 目标与范围

将 Keystone 的账号、组织权限、系统管理、监控、定时任务和管理前端迁移到 Elixir、Phoenix、Ecto、PostgreSQL 和 LiveView。保留已确定的 HTTP 路径、有效输入、响应字段和业务行为。旧 Java 项目与 `keystone-frontend` 是接口参考，不要求视觉或实现方式逐项复制。

当前采用单节点部署。PostgreSQL 保存业务数据与认证会话。Erlang 运行时内置表存储（Erlang Term Storage / ETS）只保存可以重建的验证码、缓存和本节点限流记录。它不负责跨节点同步。

本轮只更新开发计划和审查记录，不修改业务代码、迁移、依赖或部署配置，不创建发布标签。后续实施必须分别确认功能验收和发布验收，不能把“已有实现”写成“已经通过本轮验收”。

## 当前状态

### 已有实现

- 健康检查、数据库迁移、种子数据和 PostgreSQL 认证会话。
- RSA 登录、RS256 access/refresh token、会话占用、刷新、退出和强制下线。
- 用户、组织、角色、菜单、公告、配置、字典、文件和 Excel 接口。
- 登录与操作日志、定时任务、运行监控和 LiveView 管理页面。
- Redis 移除、ETS 临时数据、运行时指标、组合索引、测试工作流和 release 镜像构建工作流。

这些实现的主要功能范围已覆盖。2026-11-07 的审查仍发现认证、授权和常用页面操作缺陷，因此当前状态是“功能覆盖已建立，修复与重新验收待完成”，不是“可以直接发布”。

[`02-java-parity.md`](02-java-parity.md) 保留功能清单。该清单不替代本计划中的缺陷关闭条件，也不代表本轮重新验证了旧项目或旧前端。

### 本轮确认的主要缺口

- 重复登录的会话冲突可能抛出未处理异常（R01）。
- 用户详情、导出和修改目标部门没有完整应用数据范围限制（R02）。
- LiveView 长连接在会话撤销后仍使用旧认证状态；登录事件不检查验证码开关（R03、R04）。
- 限流记录到期后的新窗口使用了旧到期时间（R05）。
- 正常 multipart Excel 上传会被临时路径扩展名检查拒绝（R06）。
- LiveView 编辑状态、按钮字段和只读页面入口存在问题（R07、R08）。
- 批量角色分配或取消可能部分写入后返回失败（R09）。

## 后续执行顺序

### 01：认证和 LiveView 会话失效处理（P1）

负责模块：`Auth`、`Auth.Session`、`LoginLive` 和 LiveView 事件入口。对应 R01、R03、R04。

范围：

- 完整传递重复登录的已有错误值。HTTP 返回现有 `409/10210`；LiveView 显示错误且保持连接。
- 管理操作和个人资料操作执行前，核验当前会话与账号状态。会话撤销、账号停用、密码重置或权限变化后，旧连接不能继续使用旧权限。
- 使 LiveView 登录遵守验证码开关和一次性消费规则。继续保留领域层明文密码入口，供已经完成入口校验的调用方使用。
- 将刷新轮换的旧会话核验、撤销和新会话占用纳入一个明确的数据库事务边界。先补充真实并发测试，再调整实现。
- 明确 access token 到期后 LiveView 是刷新会话还是要求重新登录；不能直接复用过期认证状态。

验收条件：

- 覆盖首次、重复、强制登录，以及刷新、退出、旧 refresh token 重放。
- 同一 refresh token 并发刷新时最多一个请求成功；失败请求不返回 `500`。
- 保持 LiveView 连接，在另一入口撤销会话、停用账号、重置密码或变更角色；下一次受保护事件拒绝操作，数据库不变。
- 验证码启用时，HTTP 与 LiveView 均拒绝缺少、错误、过期及重复使用的验证码。

验证：认证数据库测试、HTTP 登录测试、LiveView 事件集成测试和真实浏览器会话失效检查。

回滚边界：认证与 LiveView 入口作为一个功能切片；保留会话表，不删除既有用户数据。

### 02：用户数据范围和角色分配规则（P1）

负责模块：`Permission`、`User`、用户与角色控制器、`AdminSupport`。对应 R02、R08。

范围：

- 将当前账号允许读取的数据范围加入查询，再执行计数、分页和导出。HTTP 与 LiveView 使用同一范围规则。
- 为用户详情增加目标范围检查；编辑用户时同时检查原目标和修改后的部门。
- 明确有用户编辑权限的账号可以分配哪些角色。角色存在性校验不能代替角色分配授权规则；规则未明确前，不扩大普通角色的可分配权限。
- Excel 导入修复前先补充范围测试设计；修复后每行执行部门与角色分配检查。
- 复查角色用户查询、批量分配和取消接口，确保它们不会绕开已确定的数据范围规则。

验收条件：

- 覆盖 `data_scope=1..5`、未指定 `deptId`、当前部门及下级、自定义部门、仅本人和越界用户。
- `rows`、`total`、详情和导出结果采用同一范围；不能先取全局最新 50 条再过滤。
- 越界读取不返回目标数据；越界写入返回既有权限错误，数据库保持不变。
- 至少准备 60 个跨部门用户，验证较早的范围内用户仍可被分页查询。
- 覆盖创建、更新、导入和角色分配的允许与拒绝场景。

验证：权限数据库测试、受限角色 HTTP 测试、跨部门导出和导入测试、LiveView 普通用户测试。

回滚边界：统一查询范围与入口授权一起交付；不得通过恢复无范围查询来处理兼容问题。

### 03：限流到期处理（P1）

负责模块：`RateLimiter`、`RuntimeStore` 与限流、防重复提交 plug。对应 R05。

范围：修正过期记录重置时的到期时间；保留当前单节点 ETS 方案，不引入外部缓存服务。

验收条件：

- 首个窗口达到上限后返回 `429`。
- 人工插入过期记录后，第一个请求建立新的有效窗口；后续请求仍受上限限制。
- 验证 ETS 清理前后、相邻窗口和同键并发请求，不通过真实长时间等待制造测试。

验证：直接测试真实 `RateLimiter`，再通过 plug 核验状态码和 `Retry-After`。

回滚边界：仅限流算法与测试，不改变公开接口的限额和单节点适用范围。

### 04：Excel 上传导入（P2）

负责模块：`Excel`、`UserController`。对应 R06，并依赖切片 02 的授权规则。

范围：在上传入口区分客户端文件名与服务器临时路径。通过内容解析和大小检查处理工作簿，不要求 Plug 临时文件以 `.xlsx` 结尾。

验收条件：

- 通过真实 multipart 解析上传 `.xlsx`，正常读取并写入允许的用户。
- 拒绝错误格式、损坏工作簿、超限文件、无效表头和范围外数据。
- 导入失败结果不含密码或文件系统路径；按现有逐行结果语义报告成功和失败。

验证：Excel 单元测试和包含真实上传解析步骤的 HTTP 数据库测试；只调用带 `.xlsx` 后缀的本地文件不算入口验收。

回滚边界：上传解析与导入测试；不改变现有用户 ID 和导出字段。

### 05：LiveView 常用操作修复（P2）

负责模块：组织、账号、系统和运维页面及其事件处理模块。对应 R07、R08。

范围：

- 配置、角色、菜单编辑保留原 ID 和已保存字段，默认值只能填补缺失字段。
- 字典 `isDefault=0/1` 显式转换；操作日志删除使用 `operationId`；任务日志结束时间使用 `endTime`。
- 普通用户可以进入个人资料与概览。具有读取权限的用户可以读取和刷新已授权面板。
- 普通角色仍按当前规则只读。监控按各项权限分别加载，不因面板可见而一次加载全部监控数据。

验收条件：

- 每个编辑场景先创建数据，点击编辑，提交修改；数据库行数不增加，ID 不变，字段正确更新。
- 默认值为否的字典数据经过编辑后仍为否；操作日志删除确实改变目标记录。
- 覆盖管理员、无管理权限用户及只有单项读取权限的用户；刷新有效，未授权事件被拒绝。
- 使用 Computer Use 验证真实窗口；没有可用窗口时记录启动和恢复检查结果，再补充有边界的自动化测试，不能声称真实窗口通过。

验证：页面组件测试、LiveView 事件与数据库集成测试、真实窗口操作。

回滚边界：按可独立验收的页面操作拆分；不同时重设计页面或改动接口字段。

### 06：批量写入和任务执行边界（P2）

负责模块：`Role`、`Job`、`Job.Scheduler`、`Job.Runner`。对应 R09 和待验证项 V01。

范围：

- 批量角色分配与取消在同一事务内核验目标和执行写入；任一目标无效时，整批保持原状态。
- 复查其他使用“先批量写、后比较数量”的删除入口，统一失败后的数据库状态。
- 补充定时任务手动执行、自动执行、并发禁止、资源上限、超时、取消、任务进程异常和日志写入失败的测试。
- 明确手动执行是否必须遵守自动执行的超时、取消和并发限制。当前两条执行路径不同，不能仅凭自动调度实现声称全部执行受控。

验收条件：

- 混合有效、不存在和已软删除用户 ID 时，分配与取消均失败且没有部分写入。
- 任务测试直接调用真实执行链，检查执行次数、进程退出、运行状态清理及日志结果。
- 测试结束后无残留任务进程；不把一次状态清理单元测试当作调度并发验收。

回滚边界：批量写入和任务执行分别交付，不修改已经共享的迁移。

### 07：发布前检查（P1 问题关闭后执行）

范围：

- 运行全量测试和生产严格编译，构建实际 release 镜像。
- 使用独立 PostgreSQL 18 测试容器执行空库迁移、重复迁移、受控初始化和升级验证；不要向已有开发库或生产库直接写开发种子账号。
- 完成就绪检查、登录、重复登录、刷新、退出、普通角色权限、LiveView 失效会话和文件上传下载检查。
- 验证上传目录的持久化挂载、运行用户写权限，以及数据库和文件备份恢复。
- 核查质量检查和镜像发布的依赖关系；镜像构建成功不能替代测试通过或启动成功。

验收条件：记录提交、镜像摘要、数据库版本、端口、启动与清理步骤、测试结果和回滚步骤。实际镜像及数据恢复检查未通过时，不创建 `v0.3.0` 标签或声称发布成功。

本轮没有发布授权。后续发布时再生成变更说明、核验镜像和发布资源；非发布任务不监测 GitHub CI。

### 08：可维护性和可选优化（P3）

在前述问题关闭后，再抽取已经重复使用的参数解析、分页和字段映射，拆分接近 600 行的模块。为现有 Telemetry 指标接入报告组件、数据库连接池指标和告警。按真实迁移需求决定 MySQL 数据导入工具；多节点方案需要单独评估调度重复执行、验证码、缓存失效和限流共享，不在单节点修复中提前实现。

## 通用验收条件

- 所有新增或修改的源代码文件不超过 600 行。
- 数据库迁移只追加，不修改已经共享的迁移；验证空库和已有数据库的升级。
- 未登录返回既有 `40101`；缺少操作权限返回 `40302`；数据范围拒绝返回 `40303`。
- 输入只在负责入口校验一次；领域函数接收已确认类型的值，负责事务与状态变更。
- 不在响应、日志、测试结果或文档中输出密码、令牌、验证码答案和服务器文件路径。
- 运行格式、源文件行数、严格编译、默认测试和相关集成测试。失败时修复根因，不降低检查要求。
- 每个功能切片单独验收和提交。提交、推送和发布按当次授权执行，不自动扩大范围。

## 本机验证方式

Docker 和 Docker 测试依赖服务通过 WSL 执行。先读取实际发行版、Docker 状态、已有容器、健康状态和映射端口。其他 Elixir 构建与测试可以在 Windows 执行，不要求迁入 WSL。

本轮核实的发行版为 `Ubuntu-24.04`。后续执行前重新检查服务和端口，不要直接重建已有容器：

```powershell
wsl --list --verbose
wsl -d Ubuntu-24.04 -- docker info
wsl -d Ubuntu-24.04 -- docker ps
wsl -d Ubuntu-24.04 --cd /mnt/f/project/keystone-phoenix -- docker compose ps
# 仅在确认需要启动项目开发服务时执行
wsl -d Ubuntu-24.04 --cd /mnt/f/project/keystone-phoenix -- docker compose up -d postgres
elixir --version
mix deps.get
mix format --check-formatted
mix check.source_lines
mix compile --warnings-as-errors
mix test
mix test --include integration
```

依赖获取必须遵守 `mix.lock`。执行测试前，将 `POSTGRES_*` 指向已核实的本地 Docker 测试实例和测试库；不要复用开发库名。本轮实际结果单独记录在 [`03-code-review.md`](03-code-review.md)，上述命令清单不代表已执行通过。

## 回滚边界

本轮文档提交可单独撤销，不改变运行时或数据。后续修复优先通过向前兼容代码回退；保留 PostgreSQL 会话表和上传文件。Redis 移除后的旧 Redis 会话不迁移，回退不能恢复这些登录状态。生产迁移回退和数据恢复必须先在独立环境验证。
