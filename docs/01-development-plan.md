# Keystone Phoenix 重写计划

## 目标

将原 Keystone 的本地账号、系统管理、监控和任务管理能力迁移到 Phoenix、Ecto、PostgreSQL、Redis 和 LiveView。迁移保留现有 JSON 响应结构、路径、字段名和认证语义。每个模块先完成数据库资源、领域查询与命令、HTTP 控制器、认证边界和测试，再接入 LiveView 页面。

## 当前基线

已完成健康检查、字典类型与数据、系统配置、用户查询、RSA 登录密码解密、RS256 access/refresh token、单账号会话控制、登录 LiveView 和管理员概览。最近的用户管理切片还包括用户新增、更新、软删除、重置密码和状态变更。

## 执行顺序

1. **组织与权限基础**：部门、岗位、角色、菜单、角色菜单关联。已完成表、种子数据、列表、详情、树形下拉、部门、岗位、角色和菜单写命令、角色授权读取和登录后的菜单数据；继续补齐角色用户分配查询。
2. **用户关联完善**：已完成个人资料、修改密码和管理员权限边界；继续补齐用户与部门、岗位、角色的关联校验和头像文件存储。
3. **公告与日志**：公告 CRUD、登录日志、操作日志，统一记录失败结果和请求上下文。
4. **监控与在线会话**：在线用户查询和强制下线、缓存状态、服务信息。
5. **定时任务**：任务和任务日志 CRUD、启停、立即执行；为任务执行增加超时、取消和失败记录。
6. **LiveView 管理页面**：按 API 完成情况迁移部门、用户、角色、菜单、配置、字典、公告和监控页面。

## 每个切片的验收条件

- PostgreSQL 迁移可重复执行，字段和原 API 契约一致。
- 未登录请求返回现有 `40101` 响应；需要管理员的请求对普通用户返回 `40301`。
- 领域层负责输入校验、事务、软删除和缓存失效；控制器只做参数分派和响应映射。
- 密码、令牌和其他敏感字段不出现在响应、日志或持久化明文中。
- 为新增行为添加针对真实实现的单元或数据库测试，并运行格式、编译、测试和集成检查。
- 需要真实窗口的 LiveView 改动使用 Computer Use 验收；无可用窗口时记录限制，不把 headless 结果当作真实窗口证据。

## 验证命令

```powershell
docker compose up -d postgres redis
mix format --check-formatted
mix test
mix precommit
```

当前工作站缺少 `mix` 和 Docker，因此数据库、LiveView 和 Mix 验证在工具链恢复前保持未完成。

## 回滚边界

每个模块使用独立提交。数据库迁移只追加，不修改已共享迁移；回滚通过反向迁移或恢复对应模块提交完成。未完成模块不进入已完成模块的提交。
