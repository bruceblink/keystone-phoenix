## 目标与范围

将 Keystone 的账号、组织权限、系统管理、监控、定时任务和管理前端迁移到 Elixir、Phoenix、Ecto、PostgreSQL 和 LiveView。保留已确定的 HTTP 路径、有效输入、响应字段和业务行为。旧 Java 项目与 `keystone-frontend` 是接口参考，不要求视觉或实现方式逐项复制。

当前采用单节点部署。PostgreSQL 保存业务数据与认证会话。Erlang 运行时内置表存储（Erlang Term Storage / ETS）只保存可以重建的验证码、缓存和本节点限流记录。它不负责跨节点同步。

## 后续执行顺序

### 01：认证和 LiveView 会话失效处理（P1）

负责模块：`Auth`、`Auth.Session`、`LoginLive` 和 LiveView 事件入口。对应 R01、R03、R04。

实施决策（2026-11-08）：

- LiveView 在每次受保护事件和任务完成回调前重新核验 access token、当前会话、账号和权限。访问令牌到期后要求重新登录，不在页面进程中自动刷新。
- 权限、管理员身份、所属部门、角色或角色数据范围变化后，旧连接拒绝下一次操作，并清空认证、列表与表单数据。
- 页面验证码使用服务器保存在当前连接中的 key。客户端不能用另一个 key 替换它。失败后生成新验证码，沿用既有一次性消费规则。
- 认证表单参数采用 Phoenix 日志过滤，覆盖密码、令牌与验证码字段。
- 数据库测试使用独立 PostgreSQL 18 容器。Codex 内置浏览器使用独立验收库，不复用已有开发库。

验收结果（2026-11-08）：原实现的重复登录异常和刷新并发失败已由真实数据库路径复现。修复后，首次、重复、强制登录、刷新、退出、旧令牌重放和验证码拒绝测试通过。保持浏览器页面连接并撤销其会话后，下一次点击返回登录页，显示失效原因并清空原页面数据。详细命令与限制见审查记录末尾的本轮补充。

后续修复（2026-11-08）：`01656cd` 将登录验密、刷新轮换、密码更新和会话撤销按用户数据库事务锁串行化。独立连接回归覆盖密码重置与刷新、旧密码登录重叠，以及密码写入失败时的事务回滚。定向认证测试 13 项通过。受控并发测试不能推算线上发生频率。

范围：

- 完整传递重复登录的已有错误值。HTTP 返回现有 `409/10210`；LiveView 显示错误且保持连接。
- 管理操作和个人资料操作执行前，核验当前会话与账号状态。会话撤销、账号停用、密码重置或权限变化后，旧连接不能继续使用旧权限。
- 使 LiveView 登录遵守验证码开关和一次性消费规则。继续保留领域层明文密码入口，供已经完成入口校验的调用方使用。
- 将刷新轮换的旧会话核验、撤销和新会话占用纳入一个明确的数据库事务边界。先补充真实并发测试，再调整实现。
- 明确 access token 到期后 LiveView 是刷新会话还是要求重新登录；不能直接复用过期认证状态。

验收条件：

- 覆盖首次、重复、强制登录，以及刷新、退出、旧 refresh token 重放。
- 同一 refresh token 并发刷新时最多一个请求成功；失败请求不返回 `500`。
- 密码重置与刷新重叠时，密码重置返回成功后，旧会话和该次刷新产生的新会话均不可继续使用。
- 保持 LiveView 连接，在另一入口撤销会话、停用账号、重置密码或变更角色；下一次受保护事件拒绝操作，数据库不变。
- 验证码启用时，HTTP 与 LiveView 均拒绝缺少、错误、过期及重复使用的验证码。

验证：认证数据库测试、HTTP 登录测试、LiveView 事件集成测试和真实浏览器会话失效检查。

回滚边界：认证与 LiveView 入口作为一个功能切片；保留会话表，不删除既有用户数据。

### 02：用户数据范围和角色分配规则（P1）

负责模块：`Permission`、`User`、用户与角色控制器、`AdminSupport`。对应 R02、R08。

实施状态（2026-11-09）：`53a21ca` 的用户查询范围、详情检查和目标部门检查已通过数据库与 HTTP 回归测试。`492205d` 明确管理员可以分配和取消角色；非管理员只能读取其数据范围内的角色用户列表，不能修改角色分配。使用 60 个范围外用户验证了先应用范围、再计数与分页。

范围：

- 将当前账号允许读取的数据范围加入查询，再执行计数、分页和导出。HTTP 与 LiveView 使用同一范围规则。
- 为用户详情增加目标范围检查；编辑用户时同时检查原目标和修改后的部门。
- 明确有用户编辑权限的账号可以分配哪些角色。角色存在性校验不能代替角色分配授权规则；规则未明确前，不扩大普通角色的可分配权限。
- Excel 导入修复前先补充范围测试设计；修复后每行执行部门与角色分配检查。
- 复查角色用户查询、批量分配和取消接口，确保它们不会绕开已确定的数据范围规则。

验收条件：

- 覆盖 `data_scope=1..5`、未指定 `deptId`、当前部门及下级、自定义部门、仅本人和越界用户。
- `rows`、`total`、详情和导出结果采用同一范围；不能先取全局最新 50 条再过滤。
- 越界读取不返回目标数据；越界写入返回既有权限错误，数据库保持不变。
- 至少准备 60 个跨部门用户，验证较早的范围内用户仍可被分页查询。
- 覆盖创建、更新、导入和角色分配的允许与拒绝场景。

验证：权限数据库测试、受限角色 HTTP 测试、跨部门导出和导入测试、LiveView 普通用户测试。

回滚边界：统一查询范围与入口授权一起交付；不得通过恢复无范围查询来处理兼容问题。
